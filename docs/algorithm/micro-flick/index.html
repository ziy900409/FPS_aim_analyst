PERFORMANCE MEASUREMENT · DESIGN PROPOSAL

Micro Flick Test
表現指標、原理與圖說

把一次短距離 flick 拆成目標提示、動作啟動、主加速、煞停、微修正、進入目標與開火，讓「快」與「準」可以被分開量測，也能被教練轉成具體訓練處方。

狀態：量測設計提案

本頁定義建議指標、事件與判讀邏輯，不表示功能已實作。槍枝模型不在場景需求內；測試採 hitscan、零散布與零後座。

測什麼 測試設計 事件與幾何 核心指標 控制指標 時機與動態 一致性 教練判讀 有效性 參考資料
01 · SCOPE

Micro Flick 真正測的是什麼

短角距目標轉移不是單一能力；它是目標選擇、快速主動作、煞停與開火時機的串聯。

正式比較推薦

提示目標模式

三個目標可同時顯示，但每個 trial 只有指定目標有效。方向、角距與目標寬度可平衡，較能把「動作表現」從選擇策略中分離。

  • 適合個人基線、A/B 設定比較、隊內標準化
  • 可合理計算方向差、Fitts throughput 與動作啟動
實戰化補充

自由選擇模式

三顆目標都有效，玩家自行選下一顆。更接近影片中的連續玩法，但時間同時包含視覺搜尋、目標選擇與手部執行。

  • 適合觀察掃視規則、路線策略與壓力下節奏
  • 命中時間不可直接命名為「純反應時間」

測試邊界

本測試不直接測 tracking、recoil control、movement shooting、戰術決策或純視覺反應。若場景允許自由選擇，必須把成績標成 choice-inclusive。

02 · PROTOCOL

先控制條件，再談玩家差異

輸入映射、目標幾何與試驗序列只要改變，指標的含義就會一起改變。

固定輸入

鎖定解析度、FOV、DPI、靈敏度、raw input、frame/tick rate；玩家固定位置，只允許 yaw／pitch。

純化射擊

hitscan、零散布、零後座、無換彈與彈藥限制；fire cadence 不得成為瓶頸。

平衡試驗

凍結 seed，平衡左右、上下、斜向與小／中角距；玩家使用同一組 trial。

分組施測

暖身 2×30 秒；正式 5×30 秒；組間休息 45–60 秒。建立基線時另一天複測。

設計原則： 秒數與閾值是首輪 pilot 的起點。正式測試前，應把測試版本、閾值、排除規則與 seed 一起凍結。
03 · EVENTS

一個 trial 的事件與角度幾何

原始資料使用視線單位向量與單調時間戳，避免像素座標受到解析度與投影影響。

事件／量可重現定義注意事項
t_anchor首 trial 為目標提示；後續為前一次有效命中自由模式另加 choice-inclusive 標記
t_move角速度超過啟動閾值並連續成立 N ticks 的第一 tick閾值與 N 必須納入演算法版本
t_enter準星第一次進入有效目標角半徑需固定邊界是否含等號
t_firetrial 第一發有效開火後續補槍另存，不覆蓋第一發
D, W, L最短角距、移動軸有效角寬、累積球面路徑長使用角度而非螢幕像素
04 · CORE KPIs

核心面板：六組訊號就夠

先看產出、成本與典型／尾端速度，再用精度和控制指標解釋原因。

OUTPUT有效命中率hit / valid second
COST射擊準確率hit / fire
SPEEDH2H P50 / P90典型與慢尾端
PRECISION開火角誤差degree
PATH路徑效率D / L
BRAKING過衝／免修正rate

有效命中率

micro-flick.effective-hit-rate-hz
↑ 較佳
N_hit / T_valid_seconds
原理
直接量化單位有效時間的產出。
搭配
必須和準確率一起看，避免用亂射換分。
排除
暫停、失焦、遙測缺口與生成失敗。

射擊準確率

micro-flick.shot-accuracy
↑ 較佳
N_hit / N_fire × 100%
原理
描述完成產出的開火成本。
解讀
極高但速度慢可能是過度保守；低且很快可能是提前開火。
保留
所有有效 miss，不做成功者偏差。

命中間隔 P50／P90

micro-flick.hit-to-hit-p50-ms · p90-ms
↓ 較佳
Δt_i = t_hit[i] − t_hit[i−1]
P50
玩家的典型連續完成速度。
P90
慢 trial、失誤恢復與偶發卡頓。
注意
首個 trial 另報 first-target time。

開火角誤差

micro-flick.shot-error-p50-deg
↓ 較佳
acos(clamp(u_fire · v_target, −1, 1))
原理
以角度量化離中心多遠，可跨解析度比較。
分解
另報水平／垂直帶符號誤差以找方向性偏差。
樣本
命中與未命中都保留。
05 · CONTROL

路徑、過衝與修正揭露煞停品質

同樣一次命中，直達中心和越過後拉回，是兩種完全不同的動作品質。

路徑效率

micro-flick.path-efficiency
↑ 接近 1
D / L, L = Σ acos(u_k · u_k+1)
原理
比較最短角距與實際走過的角路徑。
低值
弧線、抖動、回拉或多次修正。
防呆
D 過小或 L<D 超容差時標記不可判定。

過衝率／過衝量

micro-flick.overshoot-rate
↓ 較佳
N_overshoot / N_evaluable
原理
衡量主動作是否超過目標後才回拉。
診斷
高值常見於煞停不足、靈敏度不合或用力過度。

免修正率

micro-flick.correction-free-rate
↑ 較佳
N_hit_without_secondary / N_hit
原理
快速瞄準可拆成主動作與後續次動作；一次完成通常更穩定。
版本
平滑、峰值與分割規則需保存 segmentation_version。
06 · TIMING

速度不是越高越好；關鍵是何時煞停與開火

峰值速度描述能力與策略，穩定時間和 click latency 才能指出玩家是在等、在修，還是在搶。

峰值角速度

micro-flick.peak-omega-p50-dps
情境判讀
max ω(t), t ∈ [t_move, t_fire]
好訊號
高峰值＋低過衝＋高準確率。
警訊
高峰值＋多修正＋長穩定時間。
用途
找出速度能力是否超過當前控制能力。

穩定時間

micro-flick.settling-p50-ms
↓ 通常較佳
t_fire − t_primary_end
長且準
已到位但確認過久，可能過度保守。
短且 miss
煞停未完成就提前開火。
定義
主峰後進入停止速度帶並持續 N ticks。

進入目標後開火延遲

micro-flick.click-latency-p50-ms
非單向
t_fire − t_enter
偏長
可能確認過久，或在目標內仍持續修正。
近零
邊界同步開火；需看邊緣 miss。
負值
優先檢查事件對時、延遲補償與定義。

Fitts throughput

micro-flick.fitts-throughput-bps
↑ 較佳
ID = log2(D/W + 1); TP = ID / MT
原理
用角距與目標寬度正規化速度—準確度難度。
限定
僅適用提示目標與受控 D/W；先檢查模型適配。
定位
研究／跨條件指標，不作唯一 KPI。
07 · STABILITY

平均值之外，還要看尾端、弱側與疲勞

職業表現的價值常在「不容易掉下去」；P90 與區塊趨勢比一次最佳成績更接近比賽風險。

區塊內 CV 與尾端差

micro-flick.within-block-cv
↓ 較佳
CV = SD(H2H)/mean(H2H); tail = P90−P50
原理
CV 看相對節奏變異；tail gap 看偶發慢 trial。
補充
另報最長 miss streak，揭露連續崩盤。

疲勞斜率

micro-flick.fatigue-slope
→ 0 較佳
metric_i = a + b × trial_index_i + ε_i
警訊
H2H／誤差正斜率，或命中率負斜率。
統計
用穩健迴歸並回報信賴區間；小樣本不下結論。

方向不對稱

micro-flick.direction-asymmetry
越小越對稱
median(right | matched D/W) − median(left | matched D/W)
分層
左／右、上／下、斜向，並配對相近難度。
診斷
握姿、手腕範圍、滑鼠墊邊界與坐姿。
08 · COACHING

教練判讀：先守住準確率，再定位速度瓶頸

單一指標不直接等於能力；使用指標組合建立可被下一輪測試否證的假設。

速度快
速度慢
準確率高
快速且受控

看 P90、弱側與疲勞，避免只追峰值。

過度保守

檢查啟動時間、click latency 與是否已到位仍等待。

準確率低
速度超過控制

檢查過衝、主動作峰值、邊緣 miss 與回拉。

基礎控制未穩

先降低難度，確認輸入設定與視覺辨識，再談加速。

觀察組合優先假設下一步複核／訓練
峰值高＋過衝高＋settling 長加速超過煞停能力檢查靈敏度與握力；固定角距練「快起、早煞」
路徑直接＋誤差低，但 H2H 慢啟動、選擇或確認偏慢比較提示／自由模式；拆看 t_move−t_anchor
很早進目標＋click latency 長開火過度保守逐步提前點擊，同時守住準確率下限
click latency 近零＋邊緣 miss 多預判式提前開火延後少量時機；看帶符號誤差是否集中同側
右向顯著優於左向人體工學或活動範圍不對稱控制 D/W 後複核；錄影檢查握姿、坐姿與墊面
P50 穩、P90／miss streak 惡化偶發失穩或失誤恢復慢練錯誤後重置，觀察過衝 trial 的下一次表現
區塊後段速度、精度同步下降疲勞、張力或注意力下降縮短組長、增加休息，建立放鬆提示
09 · VALIDITY

資料契約與有效性護欄

保留原始 tick、事件與版本，才能讓每個衍生指標被重算、被質疑，也被修正。

原始 tick 至少保存

session_id、block_id、trial_id、單調時間戳、yaw、pitch、目標 ID／方向／角半徑、有效狀態、fire、hit、pause／focus，以及測試與輸入設定版本。

逐 trial 衍生表至少保存

t_anchor、t_move、t_enter、t_fire、t_hit、D、W、L、命中結果、排除 reason code、演算法與 segmentation 版本。

驗證順序

  1. 合成直線與彎折軌跡驗證 D、L 與 D/L。
  2. 已知偏差與跨 yaw ±180° 案例驗證角誤差。
  3. 人工標記對照動作開始、進入、過衝與分割。
  4. 重播相同 seed／輸入，確認逐 trial 可重現。
  5. 比較不同 tick rate 的敏感度。
  6. 同日、跨日複測後定義個人最小有意義變化。
  • 自由選擇模式不可把總時間稱為純反應時間。
  • 不同 FOV、DPI、靈敏度、tick rate 或目標角寬不可直接混比。
  • miss trial 不整筆刪除；只對需要命中事件的量標記缺失。
  • 暫停、失焦、遙測缺口與生成失敗使用獨立 reason code。
  • 正式測試前註冊並鎖定主要指標、閾值與排除規則。
  • SPARC／LDJ 對處理與分段敏感，先留在研究層，不放核心面板。

最重要的防誤讀

不要把任何單一數字叫作「aim skill」。Micro Flick 是一個受控切片；教練結論應由至少一個結果指標與一個機制指標共同支持，並以重測確認。

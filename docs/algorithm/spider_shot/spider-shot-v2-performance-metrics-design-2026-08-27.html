Performance measurement design

Spider Shot v2
選手表現量化設計

將 60 秒中心—周邊 flick 任務拆成「任務成果、控制機制、條件差異」三層；先建立可重複的歷史趨勢， 再用 submovement、velocity scaling、SPARC 與 LDJ-V 解釋選手為何快、準或不穩。

核心決策

初版不建立單一綜合分數。預設歷史主指標只保留一項：周邊有效命中速度；準確率、時間與停止控制作為同場解釋， smoothness 與 segmentation 指標在完成 schema v2／角度管線驗證前維持研究用途。

建議的預設主指標 spider-v2.peripheral-hits-per-minute。它在固定 60 秒協定下同時受到搜尋、切換、命中、回中心與逾時影響，最接近整體任務產出；但必須與首發命中率一起閱讀，避免把連點補救誤認為高品質表現。
尚不定義「優秀／普通／不足」絕對門檻 目前 v2 的 2.0° 目標與 10°–25° radius range 仍屬未經真人 pilot 校準的候選協定。初期只做同一選手、同一相容 cohort 的縱向比較。

三層量化模型

成果層回答「做得怎樣」，機制層回答「為什麼」，條件層回答「在哪些方向與難度發生」。

LAYER 01

任務成果

周邊 hits/min、首發命中率、命中時間。可直接用於歷史趨勢，但速度與準確率不可拆開排名。

LAYER 02

控制機制

反應、速度縮放、細修依賴、進靶逸出、SPARC、LDJ-V。用於定位訓練方向，不直接等於成績。

LAYER 03

條件差異

依目標 D_deg、radius tier 與目標 azimuth 分層，並控制 trial index 的學習與疲勞效應。

任務難度範圍

ID = log₂(1 + D / W)；D = 10°–25°，W = 2°，因此 ID ≈ 2.58–3.75 bits

v2 的目標角寬固定而位移角度連續變化，適合研究 movement time 與 peak angular velocity 是否隨目標難度系統性調節。 分析時應使用目標條件 D_deg，而不是玩家實際 segment 位移，避免 undershoot／overshoot 污染 predictor。

第一版歷史趨勢指標

這些指標可由現有事件或 canonical derivation 取得，語意對選手與教練較直接。所有 aggregate 均須回報有效樣本數 n， quality gate 非 ok 的 run 不進趨勢線。

第二階段研究與教練診斷指標

下列指標對機制診斷有價值，但目前參考文件使用舊 schema v1、pixel speed 或舊 segmentation 路徑。正式用於 v2 前， 必須轉為 schema v2、target-linked window 與角度運動學，並建立 golden parity 與真人信度證據。

研究指標 v2 建議定義 主要用途 目前狀態
Correction-free acquisition rate 成功周邊 trial 中，首次命中前只有一段 primary flick、零 micro-adjustment 的比例 第一段 flick 自足性 建議取代 count ratio
Primary Sub-movement Ratio n_primary / (n_primary + n_micro) 保留舊研究 parity 不可作主 KPI
Velocity Scaling peakOmegaDegPerSec ~ target D_deg；回報 slope、R²、95% CI 是否依距離調節出手速度 需角度化
Primary-flick SPARC 每段 primary flick 的 angular-speed SPARC 中位數與 IQR 速度頻譜平滑度 優先 smoothness 候選
Primary-flick LDJ-V 每段 primary flick 的 angular-speed LDJ-V 中位數與 IQR jerk-based convergent validation 驗證用途

Primary Sub-movement Ratio 的修訂

原指標是整場 segment count ratio。當 segmentation 習慣性地為每個 trial 產生「一個 primary + 一個 micro」時，結果會機械性靠近 0.5， 並且多次修正的 trial 會獲得更高權重。v2 應以 trial 為分析單位，優先使用 correction-free acquisition rate；原 ratio 僅保留研究對帳。

Velocity Scaling 的修訂

peakOmegaDegPerSecᵢ = β₀ + β₁ × target_D_degᵢ + direction + trial_index + εᵢ
  • β₁ > 0 才符合「較遠目標使用較高 peak velocity」的預期
  • R² 必須與 slope 符號一起閱讀；負 slope 的高 R² 不是好表現
  • 使用 target D_deg，不可使用玩家實際 segment 距離作 predictor
  • 至少覆蓋三個 radius tiers，並回報有效 n、D range 與信賴區間

SPARC 與 LDJ-V 的角色

初版教練報告優先使用 primary-flick SPARC；LDJ-V 作為一致性驗證與 outlier 交叉檢查。兩者皆不與 tracking segment 混合， 也不跨不同 sampling、filter、resampling、segmentation 或 speed source 比較絕對值。Spider Shot 是 flick-heavy 任務， n_tracking=0 不代表選手沒有 tracking 能力。

教練解讀方式

先用 hits/min 與首發命中率判斷速度—準確率型態，再用時間、落點、停止與 smoothness 指標找原因。

高產出 × 高首發率

快速且首發可靠。再看遠距 tier 與弱方向是否仍維持；避免只因固定 seed 熟悉序列而下結論。

高產出 × 低首發率

速度偏置或以連點補救。優先看 fire angle error、miss count、correction-free rate 與 overshoot。

低產出 × 高首發率

可能過度保守。拆解 switch reaction、movement execution，以及 peak velocity 是否會隨 D_deg 放大。

低產出 × 低首發率

先排除資料品質與設備相容性，再依反應、主 flick 落點、停止控制、細修依賴的順序診斷。

建議的診斷順序

  1. 確認 quality gate、完整 60 秒、有效周邊 presentation 數
  2. 查看 hits/min 與首發命中率的速度—準確率組合
  3. 用命中時間拆出整體切換效率，再看 switch reaction 與 movement execution
  4. 用 fire angle error、overshoot、correction-free rate 判斷落點與停止控制
  5. 最後用 velocity scaling、SPARC、LDJ-V 解釋動作策略，不直接貼能力標籤
  6. 依 target D_deg、radius tier、azimuth 與 trial index 檢查特定方向、難度、學習或疲勞效應

資料與相容性契約

分析單位

成果與機制指標的基本單位是一次 center → peripheral transition 對應的周邊 target window。 所有 segment、fire、hit、tracking sample 與目標條件必須透過 targetId 或明確 window anchor 對齊，禁止以純時間鄰近猜測歸屬。

Session-level condition cell

spider-v2:radius=10-25deg;width=2deg;grid=4x3;timeout=1750ms;duration=60s;shape=sphere

歷史 cohort 使用穩定的 session-level condition cell。每一個實際 transition 的連續 D_deg、azimuth 與 seed position 僅用於 per-target 分層和 regression，不應把單一 trial 的 spider:d=...;w=... 當作整場 cohort identity。

Condition attribution

  • 距離：使用目標幾何推導的實際 D_deg，並對映至三個 radius tiers
  • 方向：使用目標相對中心視線的 azimuth；不可用實際 mouse path 的 dx/dy 反推目標方向
  • 排程格：4 個 spawn azimuth quadrants 與呈現層 horizontal／vertical／oblique 是兩套分類，報告需明確命名
  • 難度：保留連續 D/W 與 Fitts ID，不只存 near／mid／far 標籤

真人 pilot 與統計驗證

指標方向合理不代表已具構念效度。正式門檻與訓練建議必須建立在可重複的真人資料上。

階段 最低建議 主要檢查 輸出
單人 baseline 至少 3 run；理想 5 run、跨 ≥2 天 熱身、疲勞、trial order、設備一致性 個人中位數、IQR、CV
Test–retest pilot 多位選手、每人多日重測 ICC、SEM、MDC、session learning 可信變化幅度
構念驗證 不同技術層級與受控難度 D/W 效應、速度—準確率、指標收斂／區辨效度 保留或淘汰指標
教練門檻 完成前述信度與效度後 實務效果量、誤判成本、跨設備泛化 版本化門檻與建議

每場最低資料門檻（暫定）

  • 首發命中率：至少 20 個完整周邊 presentation
  • 命中時間／角度誤差／overshoot：至少 10 個有效樣本，並顯示 n
  • Velocity scaling：至少 20 個有效 primary flick、涵蓋 3 tiers，且目標 D_deg 有足夠變異
  • SPARC／LDJ-V：至少 20 個有效 primary flick；另報退化、NaN 與品質排除數
  • 單一 12-cell 細分若 n 過低，不顯示好壞判斷；跨 run pooling 或使用階層模型

以上 n 門檻是工程與閱讀安全起點，不是經 power analysis 或真人 pilot 凍結的標準。

已知風險與實作前置

首發命中語意目前有誤判風險 現行 spiderShotMetrics.ts 的 firstShot.hit 使用整個 window 的 outcome；若第一發 miss、後續 fire 命中，可能仍被標為 hit。歷史 projector 必須直接驗證 firstFire 的 hit outcome，或先修正 canonical derivation。
Schema v1 指標文件不能直接接入 v2
四份參考 guide 的實作入口、資料欄位與 pixel speed 定義屬舊分析管線。v2 的正式版本需要 schema v2 ingestion、target-linked windows、角度速度、品質 flags、golden parity 與 TypeScript／Python 邊界決策。
固定 seed 可能混入序列熟悉效應
相同 seed 有利於 test–retest 標準化，但長期重複也可能使進步部分來自熟悉同一序列，而非一般化 flick 能力。pilot 應估計 run index 效應；若日後採多 seed，需版本化 seed-set，而非任意改動。
Smoothness 對處理流程敏感
SPARC 與 LDJ-V 均受 segmentation、sampling、resampling、filtering、訊號雜訊與退化 sentinel 規則影響。任何處理定義改變都必須升 metric version，不與舊值直接畫同一條趨勢線。
方向分類不可使用 movement outcome 反推
若用實際 mouse dx/dy 或 segment endpoint 分類方向，undershoot、overshoot 與彎曲軌跡會改變 trial 所屬條件，形成 outcome-dependent attribution。v2 已保存目標座標，應直接由 target geometry 分類。

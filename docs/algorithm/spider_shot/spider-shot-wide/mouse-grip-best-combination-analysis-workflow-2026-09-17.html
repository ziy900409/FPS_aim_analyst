00 / DECISION

研究問題與回答格式

本研究要回答的是「玩家使用哪個滑鼠 × 握法組合，整體 Spider Shot Wide 表現最好」，不是把滑鼠形狀、感測器或握法機制分別做因果歸因。

Primary question

三條件直接競爭

以 condition 作為三水準玩家內因子，估計每個組合的調整後表現與全部三組 pairwise contrasts。滑鼠效果與握法效果保留為解釋用對比，不取代整體排名。

condition ∈ { GPW1/1-2-2, DK/1-2-2, DK/1-3-1 }
Allowed answers

四種結論，不強迫選冠軍

輸出只能是：明確最佳、速度—準度取捨、實質等效、證據不足。任何結論都要附玩家間一致性、95% CI 與資料品質狀態。

不做未校準總分

hits/min、first-shot hit rate、median/p90 hit time 維持可解釋的原始尺度。最佳組合由明確 guardrails 與 dominance 規則決定，不靠任意權重把指標壓成一個分數。

02 / WORKFLOW

從 protocol 到最佳組合

每個階段都有輸入、工作、輸出與停止條件。品質閘或辨識性不足時，流程降級而不是偷偷補值或改口徑。

  1. 凍結 protocol

    條件、次序、seed、SESOI 與排除規則先鎖定。

  2. 建立 manifest

    玩家、滑鼠、握法與實際順序由 manifest 明示。

  3. 資料品質閘

    檢查 validity、metadata、時間與完整性。

  4. Canonical derivation

    每個周邊 presentation 建立可稽核事件錨點。

  5. 玩家內估計

    先算每位玩家、每個條件的 outcome profile。

  6. 群體階層模型

    保留 trial/run/player 巢狀結構與 order covariate。

  7. Guardrailed ranking

    品質與準度合格後，再比較速度、尾端與穩定。

  8. 報告與封存

    HTML、long CSV、模型輸出與版本化規則一起交付。

S00

Protocol freeze

先鎖研究問題，再看結果
Input

三條件設計、drill config、預計玩家數與 sessions。

Process

預註冊 primary outcomes、SESOI、pairwise contrasts、排除與敏感度分析。

Output

analysis-config 語意版本與不可事後改寫的決策表。

Stop rule

SESOI 尚未決定時只產生估計與 CI，不宣告實質優勝。

S01

Randomization & manifest

讓 condition 與 order 可分離
Input

participant ID、session、condition order、seed bank、硬體設定。

Process

三條件六種排列近似等量分配；記錄實際執行次序與偏離。

Output

單一 manifest：participant × session × order × condition × run。

Stop rule

條件只能由路徑猜測或缺少實際順序時，該 session 不進 confirmatory model。

S02

Ingest & quality gate

先決定能否解讀
Input

所有 Spider Shot Wide JSON 與 manifest。

Process

驗 drillId、schema、FOV、DPI、sensitivity、display/sim Hz、validity、overflow、pointer lock 與必要 anchors。

Output

run-level quality ledger、有效 n、排除原因與 metadata parity 表。

Stop rule

任一條件有效 runs 不足、protocol 不一致或玩家缺少條件時，降級為描述性資料。

S03

Canonical trial derivation

一列對應一次周邊呈現
Input

通過 S02 的 raw ticks、visible 與 fire events。

Process

使用既有 window、tracking、angular kinematics 與 geometry primitives；所有缺席值維持 null。

Output

trial_metrics.csv：事件錨點、outcomes、機制與品質旗標。

Stop rule

首發命中必須讀 firstFire.hit；不得以 window eventual outcome 代替。

S04

Player-level profiles

保留每位玩家的選擇
Input

trial-level long table。

Process

每位玩家 × condition 計算 hits/min、first-shot hit rate、median/p90 hit time、timeout 與穩定度。

Output

個人條件 profile、paired deltas、run drift 與左右側敏感度檢查。

Stop rule

trial 很多不等於玩家很多；個人 profile 不產生母體 p-value。

S05

Cohort hierarchical models

推估群體與玩家差異
Input

所有玩家的 long table、randomization order 與 sessions。

Process

依 outcome 選 GLMM、count model、time-to-event 或 bootstrap；玩家含 random condition slope。

Output

三條件調整後估計、三組 pairwise contrasts、95% CI 與玩家間分布。

Stop rule

模型不收斂、order balance 失敗或 CI 過寬時，不進明確排名。

S06

Guardrailed ranking

選最佳，不掩蓋取捨
Input

調整後 outcomes、SESOI、multiplicity-corrected contrasts。

Process

先過品質與準度 non-inferiority，再以 hits/min、p90 hit time、穩定度做 dominance 判斷。

Output

明確最佳／取捨／等效／證據不足，另附每位玩家的 winner distribution。

Stop rule

沒有條件通過全部 guardrails 時，禁止用平均名次強行產生冠軍。

S07

Report & reproducibility

每個結論可回到 raw trial
Input

品質表、trial data、模型估計、decision state 與版本資訊。

Process

固定報告順序：quality → n → overall ranking → contrasts → mechanisms → sensitivity。

Output

自包含 HTML、CSV/Parquet、model table、config 與 audit trail。

Stop rule

報告若無法顯示排除原因、有效 n 或 uncertainty，即不視為完成。

03 / METRICS

結果、機制、品質分層

Primary outcomes 決定最佳組合；mechanism diagnostics 只解釋差異來自 transport、braking 或 trigger，不反過來偷換主要結果。

Reaction time 的地位

因 KI-034 pre-stimulus baseline coverage 風險，reaction_ms 先作 sensitivity metric。只有 coverage 與 detector health 達到預先門檻時，才升為正式 mechanism conclusion。

04 / MODELS

符合資料生成結構的模型

trial 巢狀於 run、session 與 player；同一玩家的數百個 trial 不能當成數百位獨立受試者。主要推論單位仍是玩家。

Binary outcome

首發命中 · Logistic GLMM

first_shot_hit ~ condition + order_position + run + side + D + pitch + (1 + condition | player)
  • 輸出 adjusted probability difference（percentage points）與 odds ratio。
  • 未開火、timeout 留在分母並編碼為未首發命中。
  • 三組 pairwise contrasts 使用 Holm correction。
Rate outcome

有效命中速度 · Count model

hit_count ~ condition + order_position + run + offset(log(active_minutes)) + (1 + condition | player)
  • 優先評估 Poisson dispersion；過度離散時改 negative binomial。
  • 輸出 adjusted hits/min 與 rate ratio。
  • 永遠與 first-shot hit rate 並列。
Censored time

命中時間 · Survival / AFT

time_to_hit ~ condition + order_position + run + side + D + pitch + player frailty
  • timeout 是 right-censored，不從資料中刪除。
  • 輸出 median / restricted mean time 與條件差。
  • 另以 uncensored log-time mixed model 作敏感度分析。
Tail & robustness

p90 與一致性 · Hierarchical bootstrap

resample player → session → run; keep trials within sampled run
  • p90 不用一般 t-test。
  • 保留相依結構並估 95% bootstrap CI。
  • 報告各條件成為最佳者的 player-bootstrap 比例，但不把它當 posterior probability。
隨機順序仍要進模型

隨機化讓 condition 與 order 可辨識，但不代表 order effect 消失。模型保留 order_position、run 與 session；若某位玩家偏離排程，分析依實際次序處理並另做 per-protocol sensitivity。

05 / RANKING

Guardrailed ranking：怎麼選最佳

排名先確定「沒有用準度換速度」，再回答哪個條件提供更高有效產出。SESOI 必須在正式看結果前由 coaching／產品團隊確認。

Gate 1資料資格

有效 runs、metadata parity、randomization 與品質旗標通過。

Gate 2準度不劣

首發命中與 timeout 不得劣於最佳條件超過預設 SESOI。

Rank 1有效產出

比較 adjusted hits/min；差異須超過 SESOI 且 CI 支持。

Tie break尾端與穩定

比較 p90 hit time、run-to-run variability 與玩家一致性。

明確最佳一個條件通過 guardrails，並在至少一項主要效能實質勝出、其他項不實質退化。
速度—準度取捨最快條件在準度、timeout 或尾端時間上有實質代價；並列 profile，不選單一冠軍。
實質等效主要差異的 CI 全部落在預設 equivalence margins 內；依舒適度或偏好選擇。
證據不足CI 太寬、玩家結果異質、樣本不足、品質失效或模型無法辨識。
決策參數符號鎖定方式目前狀態

06 / OPERATIONS

多受試者實驗如何執行

未來增加玩家時，重點不是再堆更多 trial，而是讓每位玩家都完成三條件、次序平衡且跨 session 可重測。

Order balance

六種排列近似等量

ABC · ACB · BAC · BCA · CAB · CBA

每位玩家依預先產生的表分配；若跨多日，下一 session 換不同排列，避免條件永遠佔同一位置。

Seed balance

配對，但不背同一序列

建立多 seed bank。同一 matched triplet 使用同 seed 以控制刺激；seed 對 condition 的對應跨玩家與 session 輪換，避免所有人永遠背 57001。

Session structure

熟悉、正式、洗脫

每個條件先固定短 familiarization，再進等長正式 runs；條件間休息與換鼠適應時間固定並寫入 manifest。

Sample unit

玩家數決定外推能力

每條件至少累積 30 個周邊 presentations；正式樣本數依 pilot 的 player-level variance 做 simulation，不用 400 個 trial 偽裝成 n=400。

Protocol parity

硬體條件鎖定

固定 DPI、sensitivity、FOV、aspect、display mode、refresh、mousepad 與 seat setup；每份 export 都要自動對帳。

Repeatability

跨日驗證穩定性

至少兩個 sessions 才能估 condition ranking 的重測一致性；若最佳組合跨日翻轉，結果標記為個人情境依賴。

S01 的定位

現有 S01 有 3 條件 × 3 runs、共 417 次 peripheral presentations，且 seed 前綴相同；適合驗證 trial derivation、配對與報告。因玩家 n=1 且當次順序固定，只能作 pilot case，不參與未來 confirmatory cohort 的隨機順序效應估計。

07 / OUTPUTS

交付物、報告順序與誠實邊界

每個摘要值都要能回到玩家、run 與 presentation。報告不只輸出「誰贏」，也輸出為什麼能回答、哪裡仍不能回答。

Artifacts

版本化輸出

cohort_manifest.csv條件、順序、seed、session、偏離與設備設定。
quality_ledger.csvrun/trial 品質旗標、排除原因與有效 n。
trial_metrics.parquet一列一 peripheral presentation 的 canonical long table。

Report order

閱讀順序不可顛倒

  1. Protocol 與資料品質
  2. 有效 players / sessions / runs / trials
  3. 三條件 outcome profile
  4. Guardrailed ranking verdict
  5. 每位玩家的 condition deltas 與 winner distribution
  6. Mouse contrast 與 grip contrast
  7. Transport、braking、trigger 機制
  8. Order、side、repositioning、reaction sensitivity
分析實作注意

PeekWindow.outcome 是窗內任何一發命中；首發命中必須讀第一個 compatible fire 自身的 hit。命中時間 timeout 視為 censored；缺資料一律用 null 與原因碼，不以 0 取代。

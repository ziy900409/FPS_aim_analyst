00 / Decision contract

同一條流程，回答三個層次的問題

A · C1

GPW1 × 1-2-2

原文件已確認的握法標籤。完整型號、實體設備 ID 與使用設定，仍由 manifest 記錄。

B · C2

DK × 1-2-2

B − A：固定 1-2-2，比較兩個裝置配置。不能歸因到重量、形狀或感測器的單一特徵。

C · C3

DK × 1-3-1

C − B：固定 DK，比較兩種握法。C − A 仍是完整組合對比。

本流程的 1-2-2／1-3-1 指手指配置；收案時用手背／側面照片和按鍵分工確認，另記 palm、claw、fingertip 接觸型態，避免同一標籤代表不同操作。缺少 GPW1 × 1-3-1，所以不能估完整 mouse × grip 交互作用。

結論層級與可接受的說法
層級問題需要的證據

個人選用這位玩家在哪個組合下穩定受益？玩家內平衡次序、多日重複、實質差異與獨立確認。

原文件的重點／分歧最終採用原因

02 / End-to-end workflow

十個步驟，每一步都有出口

  1. S00凍結問題母體、目標、門檻、樣本計畫
  2. S01確認熟悉度手型、慣用配置、等量適應
  3. S02平衡交叉測試三條件、六種次序、多日
  4. S03品質與時間閘去重、參數、有效區間
  5. S04抽取事件與指標首發、命中、右截、原因碼
  6. S05建立個人 profile完整產出、差值、日間變化
  7. S06分層統計pilot／個人／群體分開
  8. S07做有門檻的決策最佳、取捨、等效、未定
  9. S08教練驗證機制檢視、確認日、轉移
  10. S09交付與封存建議、限制、複测、可重現檔
執行契約：品質不足的資料仍有報告出口
步驟／負責者輸入 → 工作 → 輸出停止或降級條件
S00 教練＋分析者選用問題 → 鎖定測試目標、主要指標、SESOI、排除與分析順序 → protocol + analysis config。未鎖門檻／樣本計畫：只作 pilot，不作確認性優勝判定。
S01 測試員玩家背景 → 確認握法與適應狀態 → baseline + familiarity ledger。配置不明、無法維持指定握法：先補訓或改為探索性。
S02 測試員seeded 排程 → 執行平衡 block、休息、問卷 → raw JSON + manifest + deviation log。不適／中斷：停止該次測試並留原因；不只重跑低分。
S03 分析者全部原始檔 → 去重、metadata、完整性、計時檢查 → quality ledger、各指標 eligibility。順序混淆不可辨識：轉 pilot；技術失效：按預定規則補測／降級。
S04 抽取層事件與 ticks → 版本化 canonical derivation → trial、run、matched-pair tables。必要錨點缺失只使依賴指標不可算；不填 0，不丟原始列。
S05 教練＋分析者run profiles → 看左右、首發、尾端與跨日一致性 → 個人條件比較卡。同日三個 run 不足以證明長期最佳；安排跨日確認。
S06 統計者資料層級與排程 → 描述、配對或階層模型 → 差值、CI、適配診斷。模型不收斂／不可辨識：用預註冊簡化方案或只報估計。
S07 教練＋統計者主要效應與門檻 → 執行 §08 決策 → task verdict + 推論範圍。未通過不劣閘 ≠ 已證明較差；分開標示「退步」與「未定」。
S08 教練暫定候選 → 獨立新 seed／新日期確認，再測遊戲相關任務 → 個人使用建議。改善未重現、換姿勢才成立或造成操作代價：暫緩換裝，保留取捨。
S09 分析者完整結果 → 固定報告順序、版本與追溯 → HTML + tables + config + audit。沒有有效 n、排除原因或不確定性：報告不驗收。

既有 S01 的入口：補歷史 manifest 後直接進 S03，S06 使用描述性分支，S07 為「證據不足以確認最佳」。其用途是驗證抽取與產生下一輪假設。

03 / Field protocol

讓下一輪測試能回答選用問題

以下時程是教練提出的可執行起始方案，不是文獻驗證的最佳訓練劑量。先用獨立 pilot 確认負荷與可行性，再凍結版本；不能邊看正式結果邊調整。

階段建議操作必記資料／判準
測試前明定目標為「等量熟悉後的短期表現」。另記既有習慣；若要回答充分適應後的表現，另開較長適應期研究。技能層、慣用手、手長／寬、各配置時數、近期睡眠與疲勞、預期偏好。
獨立熟悉日每條件 5 分鐘等量練習，包含右鍵控制與滑鼠歸位；順序隨機，練習資料不混入正式測量。5 分鐘不是「已熟練」保證；仍出現握法無法維持時，預先安排三條件同等追加練習或延後。
每個測量日記錄狀態、固定座位與設備；做相同 5 分鐘一般暖身。正式測量 3 個 block，每 block 含 A/B/C 各 1 個 60 秒 run。每天 9 個正式 run，正式任務時間共 9 分鐘；不要以當日最好一場作代表。
每次切換配置先休息至少 90 秒，再用獨立練習 seed 適應 60 秒；每 block 後休息 3 分鐘。記實際休息、適應時間與不適。休息不能保證清除學習／carryover；模型與敏感度仍檢查。
跨日與確認起始安排 2 個測量日、相隔 24–72 小時，盡量同時段。之後預留第 3 日，用未見 seed 確認候選與原配置。前兩日每條件 6 runs；这是可行性起點，不能保證 CI 足夠窄。確認日的 block 數與停止規則先鎖定。

六種排列完整覆蓋；seed 在 block 內配對

單一玩家的排程示意；實際分配用隨機 seed 產生並保存，不照此固定套用全體
日期Block 1Block 2Block 3
D1ABC · seed s1BCA · seed s2CAB · seed s3
D2ACB · seed s4CBA · seed s5BAC · seed s6

每個 block 內的三個 run 使用相同任務 seed，block 間使用不同 seed；練習不使用正式 seed。每位玩家都取得六種排列，但隨機決定分配日、block 次序與 seed 配對；群體再平衡各日各位置的條件分布。同 seed 只保證生成規則，配對仍要核對座標、hitbox、方向與 presentation index。

保留 previous_condition、block 次序與實際時間。統計控制不能取代設計；block 可控制已知環境差異，區塊內隨機化降低其餘順序偏差。方法依據：NIST randomized block designs。

設定控制、盲化與樣本數
  • 固定 sensitivity、DPI、FOV、aspect、解析度／縮放、weapon、hitbox、timeout、simHz、顯示模式、滑鼠墊、座椅與手臂支撐。記錄韌體、連線模式、設定 polling、腳貼、重量與 grip tape；裝置固有差異是條件的一部分。
  • 記錄自報／設定值與實測值的來源。若要比較等實體行程，另測 cm/360；若只維持相同軟體設定，結論寫成「相同設定下」，不能假設兩鼠實體增益完全一致。
  • 固定每個 run 前的滑鼠起始位置与可用行程；run 內允許自然歸位並記錄。不要只要求某握法不能抬鼠。
  • 同一句指示：「在穩定命中的前提下盡快完成。」不透露各條件即時排名；問卷先填再看結果。玩家無法對握法盲化，分析者可先看 A/B/C 代碼完成 QA。
  • 正式玩家數以獨立 pilot 的玩家內差異、日間變異、失敗率與缺失率做模擬，目標是主要 CI 精度／預設功效。每條件 30 次 presentation 只足以啟動描述，不能當樣本數充足證據。
  • 確認性計畫鎖定最大收案與複測次數；若採序貫設計，先定停止界線。不能持續加跑直到某條件顯著。
04 / Minimum data contract

補齊「為何這樣打」與「是否能持續使用」的資料

以下為建議新增的分析資料契約，不表示目前 export 已含所有欄位。分開 raw、manifest、衍生值與問卷；舊資料缺席就保留 null 與原因，不反推或偽造。

層级最低欄位來源與用途
Playerparticipant_id, dominant_hand, hand_length_mm, hand_width_mm, game_role, skill_band, habitual_mouse, habitual_grip, familiarity_hours問卷／量測；描述適用玩家與熟悉度，不用小樣本事後挖「某手型必勝」。

Run manifestrun_id, condition_id, mouse_id, grip_id, block_id, order_position, previous_condition, seed, practice_or_test, started_at, rest_sec, deviation測試員與匯出對帳；以 manifest 為條件權威，不由資料夾猜握法。
Hardware／taskbuild_id, schema_version, drill_id, config_hash, dpi, sensitivity, cm_per_360, fov, aspect, display_hz, sim_hz, timeout_ms, weapon_id值＋來源＋缺失原因。設定 polling 只能作設定紀錄，不能代替實測事件頻率。

Presentationpresentation_id, presentation_index, target_id, stimulus_key, side, D_deg, W_deg, pitch, t_visible, t_onset, t_entry, t_first_fire, first_fire_hit, t_hit, observed_until, event_observed, end_reason一列一次 peripheral 呈現；保留原始時間單位與轉換規則。首發對應目前 target 的第一個 compatible fire。

額外資料的優先序

先補 condition／order／時間邊界／熟悉度，才有公平比較；再补跨日與舒適負荷，才有個人選用；影片與 raw mouse samples 用來回答特定機制問題，不作每次測試必備負擔。

05 / Quality before outcomes

修剪任務外時間，保留真實表現代價

檢查最終處置稽核／停止條件
重複、drill、參數先去重；只納入指定 Wide 版本。非計畫中的 protocol 差異不可直接合併；planned seed bank 差異可接受。DUPLICATE_EXPORT / WRONG_DRILL / PROTOCOL_MISMATCH；全部輸入檔仍列 ledger。
Run 硬閘validity 五旗、suspect、overflow 或 pointer-lock 失效觸發時，主比較先停用該 run；保留失效原因與補測身分。INVALID_RUN。lateEventCount 非零必列示並按預定完整性規則處理，不自動當零影響。
偵測失效检查 aim 更新、onset／entry 可用率與事件排序。僅偵測器失效而 visible/fire 完整時，可保留產出與首發結果，停用依賴機制。DETECTOR_UNHEALTHY；不把「玩家沒動」與「演算法沒偵測到」混成一種。
Baseline 不足reaction 與所有依賴 onset 的指標一併標不可用／低可信，包含 onset → entry 的 movement time；逐指標傳播品質。BASELINE_SHORT；不只停用 reaction 卻保留同一 onset 算出的機制結論。
任務內失敗timeout、未開火、補槍、長尾、自然歸位與右鍵重疊，均留在主結果。只對技術缺失做排除；有效但差的表現不能清掉。
疑似 repositioning保留主分析，報標記率與排除敏感度；150 ms／2 deg/s 是原工具候選規則，跨鼠未重校準。REPOSITION_SUSPECTED；不能命名為真實抬鼠次數。
配對缺席刺激不一致或某一側不可用，只使該 pair／該指標退出配對；原列與其他可用指標仍保留。UNMATCHED_STIMULUS / PAIR_MEMBER_MISSING；逐對比報配對分母。
差別缺失保留原文件「eligible <70% 或條件差 >10 pp」作暫定技術 QA 警戒，正式前校準；只計技術不可用，不計 timeout 等行為失敗。觸發時暫停依賴該指標的確認性排名，先查原因與界限敏感度；此數字不是通用科學標準。

Active duration 的唯一計算契約

active_duration = active_end − active_start
peripheral_hits_per_min = unique_peripheral_hits / (active_duration_ms / 60000)
  1. 優先使用可靠的任務開始／結束錨點，並確認與匯出版本的計時語意一致。
  2. 若無結束事件，使用可追溯到該版本的 task duration／protocol，與 start 錨點交叉驗證。把來源、預期 60 秒及實際記錄跨度一起寫入 ledger。
  3. S01 可在上述證據成立後，從首個任務 visible 起保留 60 秒；前 3 秒倒數與已確認的錄製尾巴分別記 TRIM_COUNTDOWN、TRIM_POST_TASK。
  4. 不得用最後一槍、最後一個 visible 或最後一個非零 tick 當 active_end。任務末段等待、未命中、回中心仍屬任務成本；拿掉會偏袒失敗較多的條件。
  5. 邊界无法確定，速率為 null／boundary unknown，停止效率排名。時間窗若真中途失去資料，不能假装只是可剪除的休息。

Rate 的分母含回中心與任務內等待，因此它是完整 center–peripheral 任務的產出率，不是純外甩動作速度。每個周邊 presentation 最多計一次有效命中，避免重複 hit event 灌水。

報告必列：匯入 → 去重 → 通過 run 閘 → 有效 active 秒數 → 全部呈現 → 各指標 eligible → 配對數。分別呈現 players／days／blocks／runs／trials，不只給一個 n。

07 / Analysis tracks

分析層級要跟測試設計一致

Track P · Historical pilot

S01：描述與方法診斷

  • 完整 run 的 rate；共同 43 次前綴的刺激配對診斷。鍵為 rep + presentation_index + stimulus_key，每條件最多 129 列、每組對比最多 129 pairs。
  • 逐 run 列原尺度差與範圍；可以給配對中位差。若保留 Hodges–Lehmann，明確寫 paired estimator 與其對稱性／位移假設，不混叫平均差。
  • 原文按 presentation index 重抽的 CI，最多反映固定 run／序列下的條件式不確定性；無法涵蓋 run 漂移、序列相依或跨日變異。
  • 只有 3 個 run／條件時，不以「bootstrap 無假設」背書精度。報 run 差異與敏感度；CI 若呈現必標 exploratory。
Track I · Individual choice

新資料：玩家內選用

  • 以完整 matched block 比較 A/B/C，保留日與 block 邊界；可用受排程限制的 randomization inference 或 block 層級模型。
  • 重抽必須整包保留同 block 三條件與其 trials；跨日變異要靠實際多日量測，不能重抽 trial 假造。
  • 2 日、6 blocks 只是起始設計；若 CI 不足，結論為未定，依預定補測計畫增加日期。
  • 前兩日選候選，第 3 日新 seed 確認；預先設定改善／不劣標準，避免只重播選中的好成績。
S01 漂移只做壓力測試

可列各條件 run 斜率，以及「假設該斜率延續至空窗」的差值範圍。斜率方向相反或估計不穩時標「不可估」。即使觀察差大於這個範圍，也不能把固定順序變成隨機實驗；不做以漂移校正後的因果排名。

Track C：多玩家、重複量測的群體分析

群體目標定義為「每位玩家等權的平均條件差」。先在玩家內匯總，再對玩家平均／標準化；不能让打出較多 targets 的玩家占較大權重。玩家內 trial 數本身可能受表現影響，須檢查加權方式的敏感度。

穩定性與尾端 CIPlayer-cluster bootstrap：整位玩家全部條件、所有日期一起抽；必要時按完整 matched block 做額外敏感度。不要把三條件獨立重抽。每次重抽重新計算決策；「未定」保留在比例分母，不稱 Bayesian 勝率。

隨機效果過多而 singular／不收斂時，依预先約定改為不相關 condition slopes、較簡結構或玩家層配對摘要；報簡化理由與敏感度。大量 trial 不等於大量玩家，重複觀測的相依性必须保留。方法依據：Lazic（2010），pseudoreplication。

配對、整體效能與重測誤差的補充規則
  • 同 seed 的 presentation index 是刺激匹配，不代表同一時間或同一疲勞程度。匹配前先比較 target 座標／hitbox；sequence 多出的尾端仍保留在完整 run 效能。
  • 新研究不能照抄 43；每個 block 記可用共同前綴。前綴分析是「大家都遇到的刺激」子問題，主要完整任務估計不能只留最快／最乾淨的部分。
  • 對首發、timeout 的二元資料報明確分母與配對缺失；對 censored time 不可把上限數值當普通觀測拿去做 paired t-test／HL。
  • 有足夠重測後可估 within-player measurement error；若合適才使用 MDC95 = 1.96 × √2 × SEM，並說明 SEM 的估法與獨立誤差假設。跨條件 effect SESOI 仍由實際選用意義決定。
  • 群體平均優勝與玩家異質性可以同時成立；分開報平均效應、player slopes、實質退步者與未定比例，不因平均好就要求每位玩家換裝。
08 / Decision rules

最佳組合需要超過「看起來比較快」

先選定一組主要決策指標：首發成功率、timeout risk、hits/min、尾端時間 T。T 在獨立 pilot 後、正式研究前固定為 p90 或 RMST(τ) 其中一個；不能看哪項顯著才切換。Median 與 run 波動作必要背景。

凍結參數原尺度如何決定
δA、δF首發退步容許 pp、timeout 增加容許 pp由任務代價與教練容忍度提出，再用 pilot 檢查可測性；不是直接拿 1 SD 當門檻。
δR值得換裝的 hits/min 差以實際多完成幾次與改習慣成本討論；在正式資料揭盲前鎖定。
δT、τ尾端時間 ms、共同追蹤上限 ms來自任務 deadline、使用需求與可觀測區間，不從觀察到的勝者倒推。
分析與樣本計畫CI family、N、日期、blocks、最大補測用獨立 pilot 做精度／功效評估；未凍結的研究只報估計。

統一差值方向，避免臨場改規則

候選 c 相對對手 j：
B_A = accuracy(c) − accuracy(j)
B_F = timeout(j) − timeout(c)
B_R = rate(c) − rate(j)
B_T = tail_time(j) − tail_time(c)
以上 B > 0 均代表候選較好。

對每一組差值使用與決策一致的區間 [L, U]。三條件共有 3 組 pairwise contrasts × 4 指標 = 12 個區間。可執行的保守預設是 Bonferroni simultaneous family 95%：每個雙側區間採 1 − 0.05/12 = 99.5833%；另列一般 95% CI 供閱讀但不拿它作正式決策。若事先選 Holm 檢定／max-t simultaneous CI，整個 family 與對應界線都須一致，不能只改 p 值、不改判準。

  1. 資格閘：品質、protocol、有效重複與可辨識性通過；S01 不具確認性資格。
  2. 準度與失敗不劣：候選相對每個其他條件都須有 L_A > −δA、L_F > −δF。
  3. 效率優勢：相對每個對手有 L_R > δR，且 L_T > −δT，才能以有效產出宣告明確最佳。
  4. 效率等效時的尾端決勝：對所有未被效率優勢擊敗的對手，rate 區間整段在 [−δR, +δR] 內，且 L_T > δT；準度／失敗不劣仍須通過。不能只因 rate「不顯著」就使用此分支。
  5. 沒有完整勝者：依證據輸出取捨、等效或未定。舒適度可支持個人選用，但不能把「較舒適」改寫成「表現顯著更好」。

明確最佳

一個候選以同一套事前規則勝過其餘兩個；註明是「群體平均」或「個人」以及測試範圍。個人長期選用仍需確認日與情境驗證。

有證據的取捨

例如 rate 有實質優勢，同時首發有實質劣勢；需區間支持兩端。列各自優勢與適用情境。若只是不劣尚未證成，應標未定而非已證實取捨。

實質等效

欲稱三條件等效，全部三組對比、全部四項主要差值區間都落入各自 ±δ。只對 A/B 成立則僅稱 A/B 等效；可依舒適、熟悉與改用成本選擇。

證據不足／部分排序

區間跨實質改善與退步、p90 不可估、品質不足或固定順序混淆。可報某 pair 已有結論，整體冠軍未定；不得把 bootstrap 最常第一強稱最佳。

「p > .05」不能證明等效；實質界線需要事前定義。本頁採用 simultaneous 95% 區間完整落入界線的保守政策，與通常以 90% CI 表達的單一 α=.05 TOST 並非相同門檻。方法依據：Lakens（2017），Equivalence Tests。

教學示例：為什麼不劣未通過不等於變差？

下列為虛構數字，非本批結果，也不是建議預设門檻。假設 δA=2 pp、δR=2 hits/min。候選首發差值區間為 [−3, +1] pp，rate 差值區間為 [+3, +6] hits/min。

Rate 有實質優勢，但首發下界 −3 未高於 −2，故準度不劣尚未通過；首發上界 +1 又不低於 −2，亦未證成實質退步。正確結論是「效率優勢已見，準度代價未定，補測」，不是「全面最佳」或「已證實拿準度換速度」。

09 / Coaching loop

把差異變成可驗證的訓練與選用建議

以下是教練的待驗證假設，不是由指標直接診斷動作原因。先看匿名條件的結果，再對照 trial 時序／必要影片；一次只改一項，避免把換握法、改感度與姿勢調整混在一起。

觀察到的 profile優先追查下一次練習／複測判讀要點
產出快、首發掉Trigger margin、首發角誤差、穿越後補槍。固定其他設定，練習先可靠進靶再擊發；回到原任務規則重測。看首發能否恢復且 rate 優勢仍在；不能只挑補中後的結果。
首發穩、產出慢Movement time、進靶後等待、回中心成本。用時序區分搬運慢或過久確認；针对已確認的瓶頸練習。Reaction 不可用時，不把整體慢歸因於反應力。
高峰速、常過衝Entry ω、overshoot、手臂支撐、握壓。練習較早減速，維持相同感度；再測時間與首發。低 brake retention 本身不算成功，仍要看完成品質。
左右差／後段變差起始位置、可用墊面、歸位、疲勞。同規則重設每 run 起點，保留 run 內自然歸位；按左右與前後段複測。不為了變漂亮只排除疑似抬鼠試次。
右鍵多、逐 run 減少手指分工、玩家是否刻意、熟悉程度。在獨立適應期檢查右鍵控制；新日期重新比較。不能單凭 34→28→17 認定已學會，或認定此握法有缺陷。
短測強、負荷高舒適、不適位置、手部張力、長時段變化。在玩家可接受範圍做固定時長的後續任務；有不適即停並記錄。表現勝出與可持續使用分開；不要求忍受不適換分數。

複測要驗證兩件不同的事

Confirmation

新日期、新 seed 還成立嗎？

以固定 block 數比較暫定候選與原配置，AB／BA 次序平衡；若仍有兩個未決候選則保留三條件。維持相同準度／失敗閘與實質改善判準，單獨報確認資料，再另報合併估計。

若不重現：記為「尚未確認」，檢查適應、日狀態與區間寬度。不要只追加候選的好場次。

Transfer

在玩家要玩的情境有用嗎？

先指定目標遊戲與角色，再選 micro-flick、tracking 或遊戲內可重複情境；ADS 有效的遊戲須另外檢查右鍵操作代價。每個任務各報 profile，不平均成總分。

實戰 K/D 或勝率受地圖、對手、隊友與角色影響，只作補充。Wide 優勢先稱為「Wide 任務優勢」，通過目標情境測試才擴大使用建議。

個人選用卡的固定句型

「在［日期／配置／任務］下，［候選］相對［原配置］的首發差為［pp＋CI］、產出差為［hits/min＋CI］、尾端差為［ms＋CI］；［已／未］跨日確認，主觀代價為［紀錄］。因此［改用／維持／情境限定／補測］，下一次在［條件與日期］複測。」

10 / Delivery and acceptance

報告先交代能信多少，再交代誰比較好

  1. 資料資格：protocol 版本、來源、排除流程、邊界來源、有效 players／days／blocks／runs／trials。
  2. 時序與混淆：實際排程、缺失、練習／疲勞；S01 的固定順序警示緊貼差值。
  3. 三條件原尺度 profile：first-shot rate、hits/min、timeout、時間分布、舒適負荷。
  4. 決策：事前 margins、simultaneous CI、每對手的 guardrail 表、四種結論之一。
  5. 個人差異：player paired-delta 圖、跨日變化、未定與受損比例；平均排名不代替個人建議。
  6. 機制與敏感度：B−A 與 C−B 並列，trial microscope、左右、seed、順序、行政右截、疑似歸位、缺失界限。
  7. 教練行動：是否換裝、代價、確認日／轉移測試狀態、下一次複測與結論適用範圍。

Artifact最低內容
protocol.json條件、任務版本、排程生成規則、門檻、N／停止規則、模型與敏感度。
cohort_manifest.csvplayer × day × block × condition × run；原始路徑、實際順序與偏離。
quality_ledger.csv包含被排除／無法解析的 run、去重、時間修剪、每指標有效狀態。
trial_metrics.csv含無效／缺失的全部呈現、事件錨點、censoring、quality flags；可另供 Parquet。
run_metrics.csv／paired_metrics.csv完整 run 產出與配對刺激母體分開；補槍、timeout 不能在 pivot 時消失。
model_estimates.csv原尺度／模型尺度、一般 CI／決策 CI、family、有效 n、模型診斷。
decision.jsonscope、margins、每對手 pass／harm／uncertain、群體 verdict、個人 confirmed 狀態。
cohort_report.html／audit.json離線報告、版本與 hashes、執行環境、分析 seed、重現指令及限制。
交付驗收清單
  • 首發 hit 與 eventual hit 用「先 miss 後 hit」案例驗證，兩者不能相同。
  • 「倒數、錄製尾巴、任務末段無操作」三種案例分開；只修剪前兩者，rate 分母可追溯。
  • timeout／no-fire／session-end／缺資料分開；p90 不可估時顯示原因，無虛構時間。
  • 共同前綴只限制配對表，完整 rate 不被裁成同樣命中機會。
  • Baseline/onset 品質傳播到所有依賴指標；右鍵與疑似歸位不被靜默剔除。
  • 統計保留 player/day/block/run 相依性，群體推論與個人確認分開。
  • 三組對比、四項主要指標、多重比較 family、SESOI 與 decision verdict 相互一致。
  • 每個結論可以追回 raw → presentation → run → model contrast；失敗、缺失與未定都可見。

未來抽取實作應重用既有 canonical windows／geometry／kinematics，讓 I/O、純抽取與統計各自可驗證。落在 scripts/ 的程式需確認其專屬 typecheck 覆蓋；不沿用原文件對舊版 npm scripts 的固定假設。

00 / SCOPE

這是流程設計，不是結果

本文件定義「怎麼分析」，一個數字都不下結論。

所有指標值、Δ 與 CI 都留到 pipeline 跑完後的結果報告。這裡固定的是：哪些 trial 進得來、用哪些既有構念、怎麼配對、什麼情況下拒絕回答。

目的是讓「換了門檻」「換了母體」在 diff 裡看得見，而不是事後追認。

範圍：先只做 spider-shot-wide-v1。

同一批資料夾另有 micro_flick_three_target_test_v9 與 tracking_core_pr_3deg_14dps 各 3 runs，視 wide 的訊號大小再決定是否擴張。pipeline 的 long-format 輸出預留 drillId 欄，屆時不必重寫。

三件改變方法的實況

① 刺激序列逐位相同 ⇒ 可配對

9 個 run 的 peripheral presentation 座標序列完全一致，共同前綴 43 次。因此可以按 presentation index 配對，比單純比中位數強一級。每條件約 43 × 3 reps ≈ 129 個可配對 trial。

② D_deg 幾乎固定 ⇒ 刪掉劑量反應

實測角距 47.7°–51.9°（中位數 49.6°），不是 proposal doc 寫的 40–70°。這個 spawn 設定沒有劑量範圍，distance_slope 與 D–MT 散佈圖在本批資料上不成立，移除；D 只當雜訊共變量與分層檢查。

③ 匯出無 mouseSamples 區塊。本批資料無法比較兩隻滑鼠的 polling / sensor 層特性，只能比行為結果。已確認實驗全程 polling 與 sensor 設定維持一致，因此這不是混淆來源，而是不可量測的維度——報告中不得出現任何關於硬體取樣差異的推論。
02 / CONTRASTS

兩個對比，平等呈現

GPW1 的三個 run 使用 1-2-2 握法，這讓設計變成兩個各自控制住一個因子的對比。兩者在報告中並列、同等篇幅、同一套判準；各自的限制寫在各自旁邊，不用強弱分級去暗示可信度排序。

Contrast M · Mouse

固定握法，換滑鼠

GPW1 / 1-2-2  →  DK / 1-2-2

握法、感度、DPI、FOV、seed 全部相同，只換裝置。限制：兩組相隔約 68 分鐘，滑鼠效應與該段時間內的熱身／疲勞共線。

Contrast G · Grip

固定滑鼠，換握法

DK / 1-2-2  →  DK / 1-3-1

同一隻滑鼠、同一段時間。限制：兩組相隔約 17 分鐘，時間共線較小但非零；且 1-3-1 有大量非預期右鍵觸發，需獨立檢視是否與表現交纏。

不可當證據的恆等式：Δ(GPW1/1-2-2 → DK/1-3-1) ≡ Δ(M) + Δ(G)。這是代數恆等，不是獨立驗證。報告中不得把它呈現為「兩個對比互相佐證」。
03 / ORDER

把順序共線變成可算的數字

9 個 run 橫跨 06:56–08:32，三個條件各自擠成一團。這不是靠免責聲明處理的問題，而是一個要算出數字、放在每個 Δ 旁邊的診斷。

GPW1 / 1-2-2 約 68 分鐘空窗 · Contrast M 的共線區 DK / 1-2-2 約 17 分鐘 · Contrast G 的共線區 DK / 1-3-1

漂移外推診斷（每個 Δ 都要附）

drift_slope = 同條件內 run1 → run3 的指標斜率（單位：指標/分鐘，三條件各算一條）
drift_expected(M) = median(drift_slope) × 68 min
drift_expected(G) = median(drift_slope) × 17 min

若 |Δ_observed| ≲ |drift_expected|  ⇒  該對比標記為「與時間漂移不可分離」，只描述不歸因
同條件內只有 3 個 run，斜率本身極不穩定。因此 drift_slope 取三條件的中位數、並同時報三條件各自的值；若三者方向不一致，就直接判定漂移不可估，兩個對比一律降級為描述性。這個判定要印在結果之前，不是附註。
04 / CLEANING

資料清理與排除

原則只有一條：排除不等於刪除。每一筆被排除的 run 或 trial 都在 per-trial.csv 留一列、帶 reason code，並在報告印出逐步計數表。靜默丟掉的資料無法稽核，也無法讓別人重跑出同一個數字。清理分三級：硬閘（無裁量）、修剪（改母體不改樣本）、trial 級處置（有裁量，必須事前固定）。

Level 2 · Run-level 修剪（改母體，不丟 run）

兩段必須切掉的非任務時間

  • 倒數期修剪：9 個 run 的第一個 visible 事件皆落在 +3.0 s。前 3 秒為倒數期，一律不計入 active duration，也不產生 trial。
  • 尾端空轉修剪：GPW1 第一個 run 的錄製長度為 8713 ticks，其餘 8 個 run 皆為 8065 ticks。多出的 648 ticks（5.06 s）全為零位移，且起點正好在 tick 8066 —— 也就是其他 run 的結束點。判定為 drill 結束後的錄製尾巴，非中途中斷，以最後一個事件截斷，不丟 run。
  • 修剪後 active duration 全 9 run 一致為 60.0 s，這是所有速率型指標的共同分母。
這是本批唯一一個會實際改變結論的清理步驟。若不做尾端修剪，hits_per_min 的分母會被灌水 8%，GPW1 會被一個純粹的錄製假象拖慢——而且方向恰好會讓 Contrast M 看起來有利於 DK。修剪前後的值都必須印出來。

ADS 重疊的 trial 絕對不能排除。1-3-1 條件下有三分之一到一半的 trial 與右鍵按住重疊；把它們拿掉等於把握法效應本身挖掉，剩下的 Δ(G) 會變成「1-3-1 在它沒有誤觸的時候」與 1-2-2 的比較，那不是任何人想問的問題。正確處置是主分析全保留，另做 with/without 分層，回答「Δ(G) 有多少是由誤觸 trial 驅動的」。
repositioning 門檻的跨硬體警告：150 ms / 2 deg/s 是在單一硬體的四份 run 上校準的。本批跨兩隻滑鼠，門檻效度未經重校準。處置：逐條件報標註率；若標註率本身在條件間差異明顯，該門檻即不可作為共同排除依據，改為只分層、不排除——否則排除規則會變成對其中一個條件的系統性懲罰。
為什麼截斷到 index 43：各 run 的 presentation 數為 43–49，而數量本身就是表現的函數（完成得快 ⇒ 60 秒內出現更多目標）。若保留尾端 trial，較快的條件會貢獻較多晚期（也較疲勞）的 trial，配對母體就被表現本身污染。截到共同前綴讓三個條件面對逐位相同的刺激序列。速率型指標不受此限，因為它要的正是完整 run 的產出。

S0 · Quality gate

先決定能不能解讀，再談差異

  • 逐 run 驗 validity 五旗、suspect、lateEventCount、bufferOverflow、recorderOverflow、pointer-lock 中斷。
  • 偵測健康度：檢查每 run 的 aim 更新是否足以支撐 detection（KI-031 的靜默失效模式：低 aim update rate 讓 detected 全滅而 CI 仍全綠）。
  • 逐 trial 驗 pre-stimulus baseline coverage（KI-034）。覆蓋不足的 trial 標記，不補值。
  • 執行 §04 的三級清理：Level 1 硬閘、Level 2 修剪（倒數期與尾端空轉）、Level 3 trial 級處置，並產出排除流程計數表。
  • 疑似 repositioning 標註走 deriveRepositioningSuspicion()；門檻跨硬體未重校準，須先驗標註率在條件間是否平衡（見 §04 Level 3）。

S1 · Per-trial extraction (TypeScript)

一列 = 一次周邊 presentation

  • scripts/spiderWideCohortRunner.ts：純函式，不讀時鐘、不讀隨機、無 I/O（比照 spiderWideRepositioningRunner.ts 的分工）。
  • scripts/analyze-spider-wide-cohort.ts：唯一的 I/O 層，掃資料夾、解析條件標籤、寫 CSV。
  • 條件標籤由路徑推導：<participant>/<mouse>[/<grip>]；GPW1 無 grip 子層 → 由 manifest 明確補為 1-2-2，不得由程式猜。
  • 欄位（long format，為多受試者預留）：participant, mouse, grip, drillId, rep, runStartedAt, presentationIndex, side, D_deg, W_deg, outcomeClass + 各指標一欄 + excluded, exclusionReason, flags 三欄。
  • 被排除的 trial 仍然寫進 CSV，只是 excluded=true 並帶 reason code（見 §04）。抽取層不做刪除，清理決策全部是可查詢的資料。

S3 · Paired statistics (Python · research/)

按 presentation index 配對

  • 取 43 個共同前綴 index；每條件在該 index 上有 ≤3 個 rep 觀測，先在 rep 內保留原始 trial（不先平均），配對單位為 (index, rep)。
  • Δ 估計：Hodges–Lehmann 位移 + bootstrap 95% CI（重抽單位 = presentation index，保留 rep 結構）。比率型指標用 paired proportion。
  • 分層檢查：side（L/R）分開再看一次；D 只驗是否在條件間平衡，不做斜率。
  • 漂移診斷（§03）與每個 Δ 一起輸出，缺一不可。
  • research/ 只讀 CSV，不 import 任何 TS 模組（C-D1）；繪圖與 I/O 落在 notebook，不進 algorithms/（C-D2）。

07 / STATISTICS

統計與判準（事前固定）

配對單位：(presentation_index, rep)  ·  index ∈ 共同前綴 1..43
Δ 估計：Hodges–Lehmann 位移 + bootstrap 95% CI（重抽單位 = presentation index）
比率指標：paired proportion + bootstrap CI

雜訊尺度（MDC proxy）= 同條件 3 個 run 之間該指標的離散度
判定：|Δ| > 雜訊尺度 且 CI 不跨 0 且 |Δ| > drift_expected  ⇒  可描述為方向性差異
      否則  ⇒  「未超過測量波動」，不報方向
為什麼是 bootstrap 而不是 mixed-effects：n=1 時隨機效果結構太薄，模型給的精確度是假的。改用無模型假設的配對 bootstrap。per-trial.csv 的 long format 已預留 participant 欄，等受試者累積後直接換成 mixed-effects（condition 為固定效果，participant 與 presentation index 為隨機截距），不需重跑抽取層。
報告順序不可調換：先印資料品質與有效 n，再印漂移診斷，最後才印 Δ 與 CI。任何 Δ 若脫離這兩項單獨呈現（例如被摘出來放進簡報），即屬誤用。

09 / LIMITS

這份分析不會說什麼

不會出現的語句原因可以出現的替代說法
「DK 比 GPW1 好 / 差」n=1、順序未 counterbalance，滑鼠效應與 68 分鐘時間效應共線「在這一位受試者、這個順序下，指標 X 相差 Δ（CI …），漂移外推為 …」
任何分數、等級、percentile、常模常模需跨技能層 100+ 人；spider-shot-wide-v1 仍是 practice-only原始指標值與其配對差
「1-3-1 握法誤觸右鍵是缺陷」未區分裝置形狀、個人手型與熟悉度；且跨 rep 遞減（34→28→17）「1-3-1 條件下記錄到非預期右鍵觸發，並在三個 run 內遞減」
關於 polling rate / sensor 表現的任何推論匯出無 mouseSamples，該維度不可量測不提
「角距越大越慢」之類的劑量結論本批 D 僅 47.7–51.9°，無劑量範圍不提；D 只作平衡驗證
reaction_ms 的跨條件比較視 KI-034 baseline coverage 逐 trial 檢查結果而定通過才報；未通過則僅列為描述性欄位並註明

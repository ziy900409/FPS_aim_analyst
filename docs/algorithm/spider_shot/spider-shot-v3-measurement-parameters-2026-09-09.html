Spider Shot v3
量測參數與意涵

1. 協定固定參數

這些值不是量測結果,而是量測的前提。它們全部進匯出 metadata,並構成 compatibility cohort 的身分; 任何一項改變都會讓資料不可與既有 run 合併比較。

2. 錨點與符號

每一個構念都是這些錨點之間的差,或這些逐 tick 訊號在某個窗內的統計量。錨點的語意跨任務家族一致, 不得在任何一支 drill 內被重新解釋。

符號來源定義與意涵
t_visible visible 事件 目標出現的 sim 時刻。每顆目標一筆,並帶 zone: 'center' | 'peripheral' 與該顆的 targetX/Y/Z。這是刺激 onset,所有反應量的零點。
t_detect deriveDetectionMetrics() 玩家開始朝目標移動的推定時刻（見 §4.1 的完整判準）。不是眼睛看到目標的時刻 —— 它是視覺—動作的代理值,下界含動作起始時間。
t_first_on_target deriveTrackingSamples() 準星射線首次與該顆 hitbox 相交的 tick。這是「到位」的定義,與引擎命中判定同幾何。
t_first_shot / t_hit buildPeekWindows() 該次呈現窗內第一發 fire 的時刻／命中時刻。窗界為 [t_visible(i), t_visible(i+1)) —— v3 場上恆只有一顆目標,此序列假設成立。
ε(t) angularEccentricityDeg() 準星方向與「eye→目標中心」方向的夾角（deg）。無號 —— 只有大小,沒有方向。這一點是 §4.3 已知限制的根源。
ω(t) omegaDegPerSec() 逐 tick 準星角速度（deg/s）。⚠️ 受 render／sim 節拍不匹配影響（KI-005 同族）。
on-target trackingDerivation.isOnTarget() aim 射線（t ≥ 0）與該顆 hitbox 相交。shape: 'sphere' ⇒ ray/sphere 相交,半徑 = width / 2,與 HitDetector 完全同一套幾何。不引入任何新閾值參數。
eye origin resolveEyeOrigin() 所有角度量的原點。v3 由 scene eye (0, 1.6, 0) 提供,並在每個 visible 的對應 tick 上求值。

3. 條件參數（自變數）

這些不是表現,而是「這一次切換有多難、往哪個方向」。分析時 predictor 必須用這些目標條件值, 而不是玩家實際的軌跡位移 —— 否則 undershoot／overshoot 會污染自變數。

參數運算意涵
D_deg
角位移		 angularDistanceDeg(normalize(prevRel), normalize(currRel)),兩者皆相對各自 visible tick 的 eye 位置 從前一顆目標方向到抵達目標方向的角位移。center→peripheral 時即該顆的角半徑（10°–25°）。這是 Fitts 的 D。
W_deg
角寬		 2 · atan((hitbox.width / 2) / worldDistanceU) · 180/π 抵達目標的角寬。v3 距離恆 8 u ⇒ W 恆為 2.0°。這是 Fitts 的 W。
direction 由相鄰 zone 讀出 center-to-peripheral（拉出去）或 peripheral-to-center（回中心）。zone 不交替即擲錯。
quadrant
呈現層標籤		 方位角 45° 分箱:上／下 → vertical、左／右 → horizontal、斜向 → oblique 只對 center→peripheral 輸出。不進 condition cell,所以後續調整分箱不會改變相容鍵語意。與 spawn 用的 4 象限分箱（0/90/180/270 起算）是兩套刻意不對齊的分類。
side 抵達點相對 eye 的 x 符號（x > 0 → 'R'） eye-frame 左右分區,只對 center→peripheral 輸出;x === 0 時省略而非猜測。
⚠️ 近垂直呈現的符號可能只是浮點殘值（sin(180°) = 1.22e-16）⇒ 判讀前先用 quadrant 篩掉 vertical。

兩種 condition cell,不要混用

逐 transition（deriveSpiderShotTransitions() 的凍結構念,固定六位小數）:

spider:d=15.000000;w=2.000000

整場身分（history compatibility cohort,從不可變的匯出 snapshot 重建, 所以舊資料不會被後來的 config 改動悄悄改標籤）:

spider-v3:frame=eye-v1;scene=spider-shot-room;eye=0,1.6,0;distance=8u;peripheral-distance=8-8u;radius=10-25deg;width=2deg;grid=4x3;shape=sphere;translation=locked

建構時會強制檢查宣稱角徑與匯出 hitbox 一致（誤差 > 1e-9 即擲錯）—— 這道檢查讓「說是 2°、其實錄成別的」 這種資料不可能靜默進入趨勢。

4. 五類構念（因變數）

五類構念全部在同一組 transition 錨點上組裝,並且全部複用既有 canonical derivation —— 不存在第二套幾何。 切換反應／移動執行／停止控制／首發只對 zone: 'peripheral' 的抵達目標輸出; 回中心只作為節奏的錨點。

4.1 切換反應 switchReaction · peripheral only KI-031 阻塞

tDetectMs
baseline：t_visible 前 500 ms 窗內、對「即將出現的目標位置」算 ε(t),取 dε/dt 的絕對值,其標準差 × 3 = 門檻。
刺激後：第一個「連續 ≥ 4 個 tick 且 dε/dt < −門檻」的 run 之起點。
reactionMs
tDetectMs − t_visible
意涵
「刺激出現後多久開始把準星往目標帶」。這是視覺—動作代理值,不是純神經反應時間:它的下界含動作起始, 且判準本身要求「持續朝目標接近」,所以一個看到但先猶豫再動的 trial 會被記成較慢。
附帶旗標
anticipation（reaction < 100 ms,疑似預判）· baselineInsufficient（baseline 樣本不足或覆蓋不到 500 ms）· status: 'detected' | 'timeout'
這一類目前在真人資料上拿不到值 KI-031（🔴 未修）:60 Hz 顯示下 aim 約每兩個 sim tick 才更新一次 ⇒ dε/dt 的負值與 0 嚴格交替, 湊不出 4 連 ⇒ 四份真人匯出的 113 個周邊呈現,detected 為 0 / 113。 而 status: 'timeout' 是一個合法值（語意為「受測者從未偵測到目標」）,所以這個失效完全靜默。 詳見 §7。

4.2 移動執行 movementExecution · peripheral only

movementTimeMs
t_first_on_target − t_detect 依賴 t_detect ⇒ 同受 KI-031 阻塞
peakOmegaDegPerSec
該呈現窗 tickRange 內 |ω(t)| 的最大值
意涵
movementTimeMs 是flick 的執行時間,刻意與反應代理值分離 —— 「反應慢」與「揮得慢」是兩種不同的訓練處方。
peakOmegaDegPerSec 回答 velocity scaling:選手的峰值角速度是否隨 D_deg 系統性調節。 峰值速度對距離不敏感,通常意味著用固定的「一種揮法」打所有幅度。
限制
ω(t) 受 render／sim 節拍不匹配污染（KI-005 同族）。peakOmegaDegPerSec 是五類裡唯一在真人資料上 34/34 有值的執行量。

4.3 停止控制 stopControl · peripheral only

overshootDeg
首次進靶之後所有 onTarget === false 樣本的 ε 最大值
dropCount
首次進靶後 on→off 的次數
microAdjustCount
drop→reacquire 的段數（reacquireMs.length）。末端未回復的 drop 刻意排除 —— 那一段沒有回復時間可量
意涵
「到位之後穩不穩」。overshootDeg 量逸出幅度;dropCount 量掉靶頻率; microAdjustCount 量對細修的依賴程度。三者一起讀才有意義:低逸出 + 高細修次數 = 保守但黏不住; 高逸出 + 低細修 = 一次過頭但敢一次修回來。
已知限制
canonical TrackingSample 沒有有號誤差,所以 overshootDeg 只能量「進靶後逸出多少角度」, 不能區分 overshoot（衝過頭）與 undershoot（沒到位）的方向。這是刻意的取捨 —— 為了不建立第二套有號幾何（C-D4）。 相關 OQ-S6-16 / D-36.5。

4.4 首發 firstShot · peripheral only

hit
該呈現窗的 outcome 是否為 'hit'
fireAngleErrorDeg
t_first_shot 當時或之後第一個 tick 對抵達目標的 ε
意涵
hit 是最貼近「打得中不中」的二元成果,且不被掃射稀釋（每次呈現只認第一發）。
fireAngleErrorDeg 是連續量版本:它把「差一點」與「差很多」分開。命中率相同但角誤差分布較窄 = 更穩定的開火時機。 角誤差小於 W/2 = 1.0° 即應命中,所以這個量也能診斷「開火時已到位卻沒中」的異常。
限制
取「之後第一個 tick」引入 ±1 tick（7.8125 ms）的量化,以及該 tick 內準星已繼續移動的偏誤。

4.5 節奏 rhythm · 全部呈現（含回中心）

transitionIntervalMs
全部相鄰 visible.t 的間隔序列
medianMs / p95Ms
上述序列的 50 / 95 百分位（線性內插,空序列回 0）
意涵
整場的推進節奏。刻意包含回中心的錨點,因為回中心也要花時間,它是任務節奏的一部分。
medianMs 是典型節奏,p95Ms 是卡頓的尾巴 —— 兩者的差距比任一單值更能說明穩定性。
注意
它是唯一不依賴任何推導層的構念（只讀事件時刻）,所以也是唯一在任何取樣率下都可靠的量。p95Ms 會吃到逾時撤除的呈現。

5. 歷史趨勢指標（五個）

以上構念是逐 trial 的。進歷史趨勢的是整場聚合後的五個 metric,descriptor 目前由 v2 機械 rename 而來 （spider-v2. → spider-v3.）,尚未針對 v3 的 eye-frame 幾何重新選過（列為 OQ-62.2）。

Metric ID標籤單位／方向運算角色
spider-v3.peripheral-hits-per-minute 周邊有效命中速度 hits/min · 越高越好 60000 × 周邊命中窗數 / validDurationMs,其中 validDurationMs = 最後 tick − 第一 tick（實測時長,不是名目 60 s） 主指標
spider-v3.peripheral-first-shot-hit-rate 周邊首發命中率 % · 越高越好 100 × 首發即命中的周邊窗數 / 周邊窗數 必讀配對
spider-v3.median-peripheral-hit-time-ms 周邊命中時間中位數 ms · 越低越好 median(t_hit − t_visible),僅計命中的周邊窗 解釋
spider-v3.median-fire-angle-error-deg 首發角度誤差中位數 deg · 越低越好 median(fireAngleErrorDeg),僅計有限值 解釋
spider-v3.median-overshoot-deg 進靶後逸出角度中位數 deg · 越低越好 median(overshootDeg),僅計有限值 解釋
速度與準確率不可拆開排名 主指標 peripheral-hits-per-minute 在固定 60 秒協定下同時受搜尋、切換、命中、回中心與逾時影響, 最接近整體任務產出 —— 但它必須與首發命中率一起閱讀,否則會把「連點補救」誤認為高品質表現。 v3 沒有、也不打算有單一綜合分數。

6. 難度座標

v3 的角寬固定、角位移連續變化,所以它是一個乾淨的單變因難度設計:同一位選手在同一場內就跨越了整段難度範圍。

ID = log₂(1 + D / W)　；　W = 2.0°（固定）、D = 10°–25°　⇒　ID ≈ 2.58 – 3.75 bits

用途:檢驗 movementTimeMs（或命中時間）與 ID 是否呈線性 —— 若成立,斜率的倒數即 throughput, 可作為跨條件正規化的研究指標。

先檢查關係再用 throughput v3 的目標是提示式（一次只一顆、位置由排程給定）,沒有選擇時間混入,原則上適用 Fitts 正規化。 但 MT ~ ID 的線性必須先在資料上驗證過才能報 throughput;它是研究指標,不是 KPI。

7. 資料充足性:採集前的硬前提

顯示刷新率 < 144 Hz 的 run,五類構念裡有兩類會靜默歸零 firstSustainedDecrease() 要求 sustainedTicks: 4 個連續合格樣本, 這隱含一個從未被寫下的前提:每個 sim tick 的 aim 都會更新。

KI-031 §2 掃描出的失效邊界（aim 更新率 f 對 sim 128 Hz,零樣本比例 ≈ 1 − f/128）:

aim 更新率對應顯示零樣本比例後果
≥ 128 Hz144 Hz +≈ 0%幾乎無零樣本 ⇒ 從未在既有 fixture 上現形
≈ 120 Hz120 Hz≈ 6%偶發漏檢
≈ 64 Hz60 Hz≈ 50%（規則交替）100% 失敗

這是懸崖,不是漸進退化。而且降低門檻無效:把 preStimulusMs 降到 100、 thresholdSdMultiplier 降到 0.5（門檻 p50 由 214 → 2.2 deg/s）並用 sustainedTicks: 2, 仍是 0/34。唯一有效的變數是連續性要求。

9. 不能說的話

以下每一條都是「寧可少一個指標,不能有一個會說錯話的指標」的直接後果（C-D3 / GD-20）。

  • 沒有絕對門檻。2.0° 角徑與 10°–25° 角半徑都是未經真人 pilot 校準的候選協定值。因此不定義「優秀／普通／不足」,初期只做同一選手、同一相容 cohort 的縱向比較。
  • 不能說 overshoot 的方向。overshootDeg 是無號逸出幅度,衝過頭與沒到位在資料上不可分。
  • tDetectMs 不是反應時間。它是視覺—動作代理值,而且目前在 < 144 Hz 的 run 上根本拿不到值。
  • 不能用單一綜合分數排名。速度與準確率必須並列閱讀。
  • 不能宣稱信度。test-retest／split-half／外部效標相關都需要真人 cohort,目前不存在。在那之前,這五個 metric 只能作為縱向自我比較,不得進教練報告作為處方依據。
  • 不能跨 KI-021 修復日合併。2026-09-03 之前的匯出其 settle／overshoot／movementTimeMs 是 box 幾何算出的。
  • Python 側不得各算一套。ε／on-target／t_detect 的權威為本文件所列的 TS 實作 + docs/operational/analysis-*.md;Python research/ 側任何差異視為 bug,或屬須入帳的語意分歧（C-D4 / C-D5）。

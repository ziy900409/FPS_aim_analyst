00 / DECISION

先回答最重要的問題

不建議現在做單一總分或玩家等級。

Wide flick 同時受到角距、左右側、FOV / aspect、cm/360、滑鼠墊行程與抬鼠行為影響。未有足夠真人資料前，把它們壓成一個分數會讓權重看似精確、實際不可解釋。

第一版應交付三個主結果：周邊有效命中速度、周邊首發命中率、乾淨 trial 的命中時間；其餘指標負責診斷。

需要真人測試資料：是

引擎與公式正確性可用合成資料驗證；但 timeout 是否形成天花板、抬鼠標註效度、指標重測信度、左右差的正常範圍，以及任何常模或分數權重，都只能靠真人 repeated-measures 資料決定。

01 / CONSTRUCT

先定義「我們到底在測什麼」

`spider-shot-wide-v1` 不是一般 click speed，也不是 v3 的更難版本。它是中心與近水平視野邊緣之間的反覆大幅度視角轉移，核心構念是大幅度 ballistic flick 後的制動與首發控制。

幾何eye-frame 球面
刺激約 40–70° yaw
目標2.0° sphere @ 8 u
結構中心 ↔ 周邊交替
Target construct

應該被評分

  • 看見周邊目標後啟動視角移動的速度
  • 依角距放大 peak velocity 的能力
  • 在 2° 目標內完成制動與穩定的能力
  • 不犧牲首發命中的完成速度
  • 左右方向是否有可重現的不對稱
Non-target influences

應控制或標註，不可當分數

  • `cm/360` 與可用滑鼠墊行程
  • 疑似抬鼠重新定位、Pointer Lock 中斷
  • 離軸球的投影橢圓面積與軸比
  • FOV、aspect、顯示 Hz、mouse polling
  • trial 順序造成的熟練與疲勞

一步一步切開一次 wide flick

每個 center→peripheral trial 必須沿用同一組 canonical 錨點。先有事件，再談指標；沒有有效錨點的 trial 應標記狀態，不得以 0 補值。

04 / AGGREGATION

聚合與排除規則

保留在分母或另行報告

  • timeout：視為右截資料，另報 timeout rate
  • 沒開火：保留在 first-shot rate 分母
  • 無法 acquisition：保留 failure rate，不以 0 ms 補值
  • 所有周邊 presentation：形成 intention-to-test 母體
  • center return：不混入 peripheral flick，但可診斷節奏與回中成本

從 clean performance 分析排除

  • Pointer Lock 中斷或跨視窗失焦
  • 資料溢位、非法時鐘、必要 metadata 缺失
  • 疑似 repositioning trial：主分析排除，敏感度分析納回
  • 不同 FOV / aspect / protocol 條件不可直接合併
  • KI-031 canonical 與 sustainedTicks:1 繞道資料不可混成同一 cohort
報告順序：先印資料品質與有效 n，再印 median + p90 + bootstrap 95% CI，最後才顯示左右差與模型斜率。單場每 cell 約 5–12 筆，不足時只能描述，不應產生「左側弱項」之類確定性標籤。

06 / HUMAN VALIDATION

真人資料要做什麼、做到哪裡

專案已有四份真人 run 將疑似 repositioning 候選門檻調到 150 ms / 2 deg/s，但它們來自 n=1、單一硬體，且指示與感度共線。這足以推翻舊門檻，不足以建立族群效度或常模。

STAGE A · PIPELINE 量測可用性

確認每種硬體條件都能穩定取得 onset、on-target、shot、hit 與 side；同時量 timeout 與資料缺失原因。

建議 5–8 人 × 2 runs
STAGE B · VALIDITY 構念、門檻與重測

within-subject 操弄感度與 lift / pause / one-shot 指示；跨 2–3 日重測。正式樣本量應由 Stage A 變異做 power simulation。

起始規劃 24–30 人 × 3 sessions
STAGE C · NORMS 常模與分數

依 FPS 段位、慣用手、cm/360 與設備分層，才可估 percentile、最小可偵測改變與任何 composite weight。

至少 100+，且需跨技能層
問題合成 / 引擎資料是否足夠是否需要真人建議判準
D/W、side、事件時間是否正確足夠不需要deterministic、golden、round-trip 與幾何測試
2500 ms timeout 是否造成天花板 / 右截不足需要各技能層 timeout rate + survival curve
疑似抬鼠門檻是否可跨人 / 跨硬體不足需要event-level 標註；lift / pause 對照；靈敏度與偽陽
左右差是否為穩定個人特徵不足需要跨 session ICC / repeatability，CI 控制 D 與 order
指標能否預測實戰大角度轉移不足需要與獨立 in-game transfer task 的 convergent / predictive validity
總分權重與玩家等級不足需要大量資料預註冊權重、外部效標、holdout validation；否則不發布

最低可執行真人設計

  • 固定 FOV 75、aspect、滑鼠、滑鼠墊與 DPI；顯示器至少 120 Hz，lift cohort 使用既定 240 Hz / 1000 Hz 規格。
  • 每人跨 3 天，每天 2 個正式 run；感度順序用 counterbalancing，換感度後先給 20–30 秒適應。
  • 每個條件至少累積 30 個周邊 presentation；單一 60 秒 run 不足就保留 run 邊界再追加，不直接拼接時序。
  • lift validity 採 `lift / pause / oneshot` 三種 instruction class 與 KeyL event-level annotation；抽樣用高速錄影人工稽核，估 annotation 誤差。
  • 主結果先估 test-retest reliability、SEM / MDC，再決定是否能顯示「進步」。左右差與 distance slope 使用 mixed-effects model。
